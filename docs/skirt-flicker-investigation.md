## 5. 到達した最有力機構（ここから再開する）

ユーザーの決定的な新情報: **「これが起きるのは手がスカートに触れているとき」**

### 5.1 焼き込みデータから計算した事実

`frontend/physics/miku-hair-physics.json` の剛体マスクを Bullet の双方向判定
（`(1<<groupA) & maskB && (1<<groupB) & maskA`）で全ペア計算した結果:

```
スカート(group 9, mask 0xfdaf) が衝突する:   上半身2 / 首 / 頭 / 肩 / 腕 / ひじ / 足 / ひざ / 足首 / Dx
スカート が素通りする:                        右手首・左手首 (group 14, mask 0xbdff, sphere r=6.4cm)
                                             下半身 / 下半身辅(股間の大球 r=20.8cm) / 上半身
```

**手首のマスクはビット9（スカートのグループ）が落ちている → 手はスカートの布を
物理的に素通りする。** 腰・股間の大球も同様に素通り（裾が腰まわりの空隙に入れる）。

### 5.2 幾何の実測

- 指と裾ボーンの**最接近 1.9mm** — 通常のアイドル中に指が布の中にある
- 手が布の中にあるとき（<1cm）、**裾ボーン126本の振動が約5倍**になる

裾ボーンの世界座標の**2階差分**（なめらかな揺れを除いた振動成分のみ、mm/frame²）:

| 手と裾の距離 | フレーム数 | 振動 中央値 | 最大 |
|---|---|---|---|
| **1cm未満（布の中）** | 691 | **0.525** | **11.2** |
| 1〜2cm | 2209 | 0.189 | 8.5 |
| 4〜8cm | 818 | 0.112 | 5.8 |
| **8cm以上** | 1663 | **0.107** | 4.1 |

最悪ジッタのフレームは**一貫して `ひじ補助R ~ スカート_0_13`**（腰に近い最上段リング）
のペア。腕の補助ボーンのカプセル（これは実際に衝突する）が上段の布を押している構図。

### 5.3 だから次に測ること

**「振動している裾ボーンを、どのカプセルが押しているか」** を特定する。
- 各フレームで、振動最大の裾ボーンに対し全キネマティック剛体との距離・貫入量を計算し、
  押している剛体を名指しする
- `ひじ補助R/L`（腕の付与親ボーン）のカプセルが犯人なら、その半径/位置が
  過大か、あるいは `vrmMotionPlayer.syncAppendBones()` が毎フレーム書き直す
  付与親ボーンとの相互作用で振動している可能性を疑う

**候補の修正**（未検証・優先順）:
1. スカート ⇄ 手首（group 14）の衝突を有効化 — 手が布を素通りしなくなる。
   ただし過去に「全マスク反転」「スカートのみ反転」が2回失敗している経緯があるので
   **ペア単位で足す**こと（`mmd-hair-physics.ts` の `addRigidBody` 直前でマスクにビットを追加）
2. スカート ⇄ 下半身辅 の衝突を有効化 — 腰まわりの空隙を埋める
3. Bullet ソルバの `m_splitImpulse = true` — 「貫入回復の衝撃で吹き飛ぶ」の定番対策。
   現在ソルバ設定は一切触っていない（デフォルト10反復、splitImpulse オフ）
4. `ひじ補助` カプセルの半径を絞る

## 7. 計測を壊した罠（全部実際に踏んだ。ここが一番の資産）

1. **`taaSettle`（決定論ラッチ）は保持フレームを再生する。** ラッチ中は
   **ライブの材質変更が画面に一切反映されない**。これで「q02 を隠しても 0.00%」
   「全布 DoubleSide 化しても DOM しか変わらない」という**偽の陰性**を量産し、
   材質帰属の探索を丸ごと無効化した。**計測時は必ず `taaSettle: 0`**
2. **`__space()` は localStorage に永続化する。** 別スクリプトが残した
   `cameraDrift: 0` がカメラドリフトを止め、**taa=0 の基準値が 2.05% → 0.68% に落ちて
   TAA が退化に見えた**。ツールは実行前後に `localStorage.removeItem("vrmSpace1")`
3. **GLSL はテンプレートリテラル。** コメント内のバックティック（`` `fast` ``）が
   文字列を終わらせ、ビルドが `Expected ";"` で落ちたまま**古いバンドルで
   「効果なし」と測っていた**。ビルド後は `Deployed main-XXXX.js` と
   `grep -c <新uniform名> frontend/assets/main-*.js` を必ず確認
4. **背景タブは rAF が止まる。** 2ページを同時に stepFrame するとデッドロックする。
   クロックが決定論的なので**逐次実行して frame i 同士を比較**すればよい
5. **ページを閉じ忘れると溜まる。** 8枚で WebGL コンテキストを食い潰し
   `__AI_DEBUG__` が出てこなくなる。スクリプトは finally で必ず close
6. **Playwright のスクリーンショットは約8fps。** 60fps の1〜2フレーム事象は
   原理的に撮り逃す。**ページ内 rAF で縮小画像の差分を毎フレーム取り、
   リングキャンバスから前後フレームを回収する**のが正解
7. **「一瞬」の事象の機械的定義**: `d(prev,cur)大 && d(cur,next)大 && d(prev,next)小`
   （=1フレームだけ出て消えた）。正当な速い運動は3番目の条件で落ちる
8. **単発の劇的な数字を信じない。** 一度だけ「内部エッジ -99%」が出て報告したが、
   3回測り直して再現しなかった（-53〜-63%が真値）
9. **スイング中の own-diff はシマー計測に使えない**（正当な運動が支配する）。
   シマーは「ポーズ凍結＋カメラのサブテクセルドリフト」で運動成分を最小化し、
   **max と median の乖離**として読む
10. **ボーン名で系統を判断してはいけない。** ネクタイのボーンは `D1..D8` で
    「ネクタイ」を含まず、`/ネクタイ|タイ|リボン/` の grep は0件だった
11. **springbone のコライダー群は実行時ほぼ無関係。** `applyBodyColliders` が作る
    脚・腰のコライダーは ammo 読み込み失敗時のフォールバック専用で、
    スカート・髪・ネクタイは Bullet が所有している（ハンドオーバーで
    springbone ジョイントが削除される）。ここで半日溶かした

## 8. 「ちらつき」という一語の下に同居していた別現象（重要）

最終的に**4つの別問題**だったと判明した。混同すると必ず迷子になる:

1. **シーン全体のエッジのクロール** — 時間方向処理の不在 → TAAで解決
2. **テクスチャのシマー** — 2048pxテクスチャのミップマップ欠如 → 直せるが見た目が変わる
3. **高コントラスト柄の正当な運動** — 数px幅の明るい柄が布の変形で動く。
   解像度2倍でも変わらない＝コンテンツ特性
4. **ネクタイの物理貫通** — 腰を突き抜けて脚の間から出る（修正法は判明・現在は取り消し）
5. **スカート内側のちらつき（未解決）** — 手が布に入ると布の振動が5倍

ユーザーの**現象そのままの記述**（「表の白と水色が紺の部分から出てくる」
「手がスカートに触れているとき」）が毎回突破口だった。
**言葉を仮説に翻訳する前に、記述どおりの検出器を作ること。**
